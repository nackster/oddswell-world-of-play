# Phase 0.6N: Athlete Performance Scope Freeze and Phase 1 Handoff

## Decision

Select **no additional Athlete Performance input**. Phase 0 is frozen except for a demonstrated defect in an existing contract.

The current stack already separates durable ability, shooting reliability, opportunity, fatigue, minutes, availability, career progression, and bounded off-court choices. Another performance input would be speculative tuning without a measured product need. Cost: **$0.00**.

## Frozen Phase 0 stack

- Athlete Life Brain v4 remains the default for new train, rest, recover, and socialize choices.
- Consistency v2 remains the shooting-only active default.
- Offensive Involvement v1 remains the baseline-policy active default with `OPPORTUNITY ONLY` scope.
- League state v6 remains the current stored-history contract.
- Every authoritative outcome continues to come from the event log and its stored versioned snapshots.
- Archived replay and Admin surfaces remain read-only representations of that evidence; neither may reinterpret or resimulate an outcome.
- Existing truth labels, historical version pins, migration behavior, and one-switch rollback boundaries remain unchanged.

This freeze does not claim real-world realism, learning, intelligence, confidence, personality, neural-network training, or correct real-world player usage.

## Evidence required to reopen athlete-performance scope

A deferred idea may return to selection review only when at least one measurable trigger exists:

1. A first-playable test records a named player-facing experience failure that the frozen fields cannot represent.
2. A preregistered controlled evaluation shows the current stack misses a defined target by at least 10% across at least 1,000 paired seeds, while ratings, role, health, and matchup are held constant.
3. A verified replay, persistence, migration, or Admin audit exposes a defect in an existing frozen contract.

Passing, defense, rebounding, clutch behavior, longer Life Brain memory, personality, stories, legal trouble, and permanent life-driven rating changes remain backlog ideas—not scheduled phases—until one of these triggers is met. Any reopened proposal must still begin as one bounded opt-in input with exact replay evidence and no automatic promotion.

## Phase 1 handoff

The next gate is **Phase 1A — One-Block 3D Vertical-Slice Engine Benchmark**.

Use placeholders to test one compact street block, one court, one controllable rigged avatar, basic lighting/collision/navigation, a few placeholder NPCs, and an adapter that renders one existing authoritative replay. The 3D client must consume recorded event-log outcomes and must never run a second basketball simulation.

The benchmark must record packaged-build frame time, memory use, build time, and one representative asset-iteration time before an engine or engine version is frozen. It does not authorize an engine installation, final city art, economy, credits, wagering, deployment, paid APIs, or model training.
