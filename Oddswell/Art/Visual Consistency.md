# Visual Consistency

## Goal

Every OddsWell character, city, team, item, apartment, interface element, and promotional image should feel as though it belongs to the same authored universe.

## Owner direction — 2026-09-12

The owner's follow-up explicitly selects the first generated street picture as the graphics target and authorizes continued modeling and rendering toward it. The active target is therefore that more realistic warm civic scene, rather than the earlier unresolved painterly alternative. [[Art/Production/SundaleStreetSlice/README]] contains the resulting editable Blender street slice and native renders. It advances the modeled scene; it does not silently replace the tested game map or promote the static anatomical study to the gameplay rig.

OddsWell must have a distinguished visual identity that a player can recognize from a screenshot. The owner explicitly wants something different from the assistant's usual visual defaults. This is a product requirement, not a claim that the current graybox or character candidate already achieves it.

Review the character, clothing, architecture, materials, lighting, and interface together at the actual gameplay camera. A logo or the word OddsWell cannot carry recognition alone. Future visual reviews should include an ordinary street view, the same character near the arena, and a home/interior view with identifying text hidden. Ask whether their silhouettes, surface treatment, color relationships, and recurring forms visibly belong to the same game.

Start from the accepted warm civic-commons direction and later six-district business-clustered planning baseline in [[Design/Sundale Production Asset Scope]]. Preserve their distinction from the smaller validated production map. Present concrete visual candidates before promoting new proportions, a different art style, or a city redesign to canonical production. The current shared-skeleton mannequin proves the animation and clothing pipeline; its primitive surfaces are not final character art.

The first character-and-street review is available in [[Art/Reviews/OddsWellStreetIdentityCandidate/README]]. It includes a native Blender scale/layout study, a generated direction concept, and current packaged street, shared-city, and Studio captures. The comparison is at gameplay scale, not an identical camera or implemented recreation. Proposed rules: warm mineral stone and terracotta, blue courts, mature green canopies, human-scale shopfronts, a readable arena silhouette, and a scarce narrow teal band connecting clothing and civic fixtures. The generated image is more realistic than the requested sculpted/painterly treatment; the amount of stylization remains a decision. The back/shoulder jacket band and detailed assets are proposals, not changes to canonical production assets.

The runtime now uses the shared skeletal body and clothing with movement-driven animation; its geometry and materials remain a technical candidate. Next, establish the repeatable visual rules in one small production street slice with a refined character and jacket before expanding the asset family. Recognition and visual quality need owner review; passing import or regression tests does not establish them.

## Canonical hierarchy

1. Approved art-direction rules.
2. Approved master character and item references.
3. Approved 3D production assets.
4. Exploratory generated images and videos.

When generated material conflicts with an approved rule or reference, the approved material wins.

## Visual bible requirements

Before producing a large asset library, define and approve:

- Character proportions and silhouette language.
- Face, hair, body, and clothing stylization.
- Item shape language and detail density.
- Material and surface treatment.
- Color palettes for the world, cities, and teams.
- Lighting, atmosphere, and weather rules.
- Camera, lens, composition, and presentation rules.
- Graphic-design, typography, icon, and logo rules.
- Explicit examples of what does not belong in the game.

## Character consistency workflow

1. Explore several visual directions.
2. Approve one character style and proportion system.
3. Create a master reference sheet with front, side, back, face, expression, clothing, scale, and color references.
4. Use the same approved reference set for later generations.
5. Store approved references and generation notes locally.
6. Build and validate the final character as a production-ready 3D asset.

## Item consistency workflow

1. Assign each item to a city, team, culture, manufacturer, or neutral world style.
2. Reuse approved shape, material, color, and detail rules.
3. Generate controlled variations from the same reference family.
4. Approve a concept sheet before 3D production.
5. Validate the final model beside existing approved characters and environments.

## Tool roles

### Higgsfield AI

Use for consistent character references, concept variants, item presentation, storyboards, cinematic previsualization, and image-to-video exploration. The project owner has an active subscription. Announce intended use before consuming paid generations.

### Conversational image generation

Use for rapid ideation, focused edits, mood exploration, and reference variations when it is faster to work directly in the development conversation.

### 3D production tools

Use Blender or the selected engine pipeline for final geometry, topology, UVs, materials, rigs, animations, LODs, collision, and optimization. Generated images guide production but do not replace these steps.

## Current decision

Do not generate large quantities of characters or items until the first city's art direction and the base character system are approved. Consistency is established with a small canonical reference set first.
